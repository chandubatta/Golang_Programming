# `crypto/hmac` Package in Go

The Go standard-library `crypto/hmac` package implements **HMAC
(Hash-based Message Authentication Code)**. HMAC combines a
cryptographic hash function such as SHA-256 with a **secret key** to
produce a message authentication code (MAC). A receiver who knows the
same secret key can recompute the HMAC and verify that the message was
not modified and came from someone possessing the secret.

Official documentation: https://pkg.go.dev/crypto/hmac

------------------------------------------------------------------------

## 1. What is `crypto/hmac`?

Normally, a hash works like:

``` text
message
   ↓
SHA-256
   ↓
hash
```

Anyone can calculate the hash.

With HMAC, a **secret key** is also involved:

``` text
message + secret key
          ↓
        HMAC
          ↓
      MAC/signature
```

Only someone who knows the secret key should be able to generate the
correct MAC.

For example:

``` text
Message:
    "amount=100&user=123"

Secret key:
    "my-secret-key"

HMAC-SHA256:
    8f4c...abc123
```

The server can calculate the HMAC again and compare it with the received
value.

### What HMAC provides

-   **Authentication** --- proving that the sender possesses the secret
    key.
-   **Integrity** --- detecting whether the message was modified.
-   **Request signing** --- signing API requests.
-   **Webhook verification** --- checking whether a webhook was
    generated by a trusted service.
-   **Token signing** --- creating integrity-protected tokens.

### What HMAC does NOT provide

HMAC does **not encrypt** the message.

For example:

``` text
message = "hello"
```

After HMAC:

``` text
message = "hello"
HMAC    = "9a7f..."
```

The receiver can still see `"hello"`.

If you need confidentiality, you need encryption, such as an
authenticated-encryption scheme.

------------------------------------------------------------------------

## 2. HMAC vs Hash

This distinction is extremely important.

### Hash

``` go
hash := sha256.Sum256(message)
```

Anyone can calculate it.

``` text
SHA256("hello")
       ↓
2cf24dba...
```

### HMAC

``` text
HMAC(secret, "hello")
       ↓
a cryptographic authentication code
```

Without the secret key, an attacker cannot normally generate a valid
HMAC for a modified message.

``` text
Hash:
    Message → Hash

HMAC:
    Secret Key + Message → MAC
```

------------------------------------------------------------------------

## 3. Functions in `crypto/hmac`

The `crypto/hmac` package has two exported functions:

``` go
func New(h func() hash.Hash, key []byte) hash.Hash

func Equal(mac1, mac2 []byte) bool
```

These are the functions you should learn thoroughly.

------------------------------------------------------------------------

## 4. `hmac.New()`

### Function signature

``` go
func New(h func() hash.Hash, key []byte) hash.Hash
```

`New` creates a new HMAC hash using:

1.  A hash function
2.  A secret key

For example:

``` go
mac := hmac.New(sha256.New, key)
```

Here `sha256.New` specifies that HMAC should use SHA-256, while `key` is
the secret key.

### Why does `New` accept a function?

Notice that we pass:

``` go
sha256.New
```

not:

``` go
sha256.New()
```

That's because `hmac.New` expects:

``` go
func() hash.Hash
```

It wants a function that can create a new hash instance.

This allows different hash algorithms:

``` go
hmac.New(sha256.New, key)
hmac.New(sha512.New, key)
```

### Simple example

``` go
package main

import (
    "crypto/hmac"
    "crypto/sha256"
    "fmt"
)

func main() {
    key := []byte("my-secret-key")
    message := []byte("Hello, Go!")

    mac := hmac.New(sha256.New, key)

    mac.Write(message)

    signature := mac.Sum(nil)

    fmt.Printf("HMAC: %x\n", signature)
}
```

The important sequence is:

``` go
mac := hmac.New(sha256.New, key)
mac.Write(message)
signature := mac.Sum(nil)
```

------------------------------------------------------------------------

## 5. Understanding `mac.Write()`

Although `Write()` is not declared specifically by `crypto/hmac`, it is
part of the `hash.Hash` interface returned by `hmac.New`.

``` go
mac.Write(message)
```

You can feed data into the HMAC incrementally:

``` go
mac.Write([]byte("Hello "))
mac.Write([]byte("World"))
```

This effectively processes:

``` text
Hello World
```

This is useful when the message is large.

``` go
mac.Write(header)
mac.Write(body)
mac.Write(footer)
```

You don't necessarily need to construct one enormous byte slice first.

------------------------------------------------------------------------

## 6. Understanding `mac.Sum(nil)`

`Sum()` also comes from the `hash.Hash` interface.

``` go
signature := mac.Sum(nil)
```

It returns the current HMAC value.

For HMAC-SHA256, the result is **32 bytes**, because SHA-256 produces a
256-bit/32-byte digest.

You can print it in hexadecimal:

``` go
fmt.Printf("%x\n", signature)
```

### Important detail

`Sum()` does not reset or destroy the current hash state.

If you want a fresh HMAC computation, create a new HMAC object or
appropriately reset/reinitialize your computation.

------------------------------------------------------------------------

## 7. `hmac.Equal()`

### Function signature

``` go
func Equal(mac1, mac2 []byte) bool
```

This function compares two MAC values in a way designed to avoid leaking
timing information.

Suppose a client sends a message and signature. Your server calculates
an expected MAC.

Use:

``` go
if hmac.Equal(receivedMAC, expectedMAC) {
    fmt.Println("Valid")
} else {
    fmt.Println("Invalid")
}
```

For cryptographic MAC verification, use `hmac.Equal()` rather than
implementing your own early-exit comparison or converting the MACs to
strings and comparing them.

------------------------------------------------------------------------

## 8. Complete Signing + Verification Example

``` go
package main

import (
    "crypto/hmac"
    "crypto/sha256"
    "fmt"
)

func generateMAC(message, key []byte) []byte {
    mac := hmac.New(sha256.New, key)
    mac.Write(message)

    return mac.Sum(nil)
}

func verifyMAC(message, receivedMAC, key []byte) bool {
    expectedMAC := generateMAC(message, key)

    return hmac.Equal(receivedMAC, expectedMAC)
}

func main() {
    key := []byte("super-secret-key")
    message := []byte("user=123&amount=500")

    // Sender creates MAC.
    signature := generateMAC(message, key)

    fmt.Printf("Signature: %x\n", signature)

    // Receiver verifies MAC.
    valid := verifyMAC(message, signature, key)

    fmt.Println("Valid:", valid)

    // Attacker modifies the message.
    modifiedMessage := []byte("user=123&amount=900")

    valid = verifyMAC(modifiedMessage, signature, key)

    fmt.Println("Modified message valid:", valid)
}
```

Conceptually:

``` text
Sender
   │
   │ message + secret key
   ▼
HMAC-SHA256
   │
   ▼
signature
   │
   ├──────── message ────────► Receiver
   └──────── signature ──────► Receiver
                                  │
                                  ▼
                              HMAC-SHA256
                                  │
                                  ▼
                           expected signature
                                  │
                             hmac.Equal()
                                  │
                         ┌────────┴────────┐
                         ▼                 ▼
                       Valid            Invalid
```

## 9. Why the Secret Key Is Important

Consider:

``` go
message := []byte("amount=100")
```

An attacker changes it to:

``` text
amount=1000
```

The attacker could calculate a normal SHA-256 hash of the modified
message.

But they cannot normally create the correct HMAC without the secret key.

``` text
SHA-256:

Attacker knows message
       ↓
Can calculate hash
```

Whereas:

``` text
HMAC:

Attacker knows message
       ↓
Does NOT know secret key
       ↓
Cannot normally produce valid MAC
```

------------------------------------------------------------------------

## 10. HMAC Is Symmetric

HMAC uses the **same secret key** for generating and verifying the MAC.

``` text
              SECRET KEY
                  │
        ┌─────────┴─────────┐
        ▼                   ▼
     Sender              Receiver
        │                   │
        ▼                   ▼
     HMAC                  HMAC
        │                   │
        └────── compare ────┘
```

Compare that with public-key signatures such as Ed25519:

``` text
Private key → Sign
Public key  → Verify
```

With HMAC:

``` text
Secret key → Generate MAC
Secret key → Verify MAC
```

Anyone who has the HMAC secret can generally both verify and create
valid MACs.

That matters significantly when designing distributed systems.

------------------------------------------------------------------------

## 11. Choosing the Hash Algorithm

You can combine HMAC with different cryptographic hash functions.

### HMAC-SHA256

``` go
hmac.New(sha256.New, key)
```

Usually an excellent default for new applications.

### HMAC-SHA512

``` go
hmac.New(sha512.New, key)
```

Also available when SHA-512 is appropriate.

The general pattern is:

``` go
hmac.New(hashFunction, key)
```

The `crypto/hmac` package provides the HMAC construction; the underlying
hash comes from packages such as `crypto/sha256` or `crypto/sha512`.

## 12. Three Common Beginner Mistakes

### Mistake 1: Thinking HMAC encrypts the message

HMAC provides **authentication and integrity**, not confidentiality.

If you need secrecy, use appropriate authenticated encryption rather
than HMAC alone.

### Mistake 2: Comparing MACs incorrectly

Correct:

``` go
if hmac.Equal(receivedMAC, expectedMAC) {
    // valid
}
```

Use the cryptographic comparison function supplied for MAC verification.

### Mistake 3: Treating HMAC as a digital signature

HMAC:

``` text
same secret
    ↓
generate + verify
```

Public-key digital signature:

``` text
private key → sign
public key  → verify
```

If you give an HMAC secret to multiple independent parties, all of them
can potentially create valid HMACs.

HMAC is therefore particularly suitable when the communicating parties
belong to an appropriate shared-secret trust model.

## 13. Real-World Application #1 --- Webhook Verification

Imagine a payment provider sends:

``` http
POST /webhook
```

with:

``` json
{
    "order_id": 123,
    "amount": 500
}
```

The provider and your server share a `webhook_secret`.

The provider calculates:

``` text
HMAC-SHA256(webhook_secret, request_body)
```

and sends the result in a header.

Your server independently calculates the HMAC and checks:

``` go
hmac.Equal(receivedSignature, expectedSignature)
```

If they match, the signed data has not been modified without detection
and the sender demonstrates possession of the shared secret.

This pattern is useful for payment notifications, webhook systems,
internal services, and API callbacks.

------------------------------------------------------------------------

## 14. Real-World Application #2 --- API Request Signing

Suppose you have:

``` text
Client
   │
   │ API request
   ▼
Server
```

A request might contain:

``` text
POST /api/payment

user=123
amount=500
timestamp=...
```

The client calculates something like:

``` text
HMAC-SHA256(
    secret,
    HTTP method + path + timestamp + body
)
```

and sends the MAC along with the request.

The server reconstructs the exact same signed input and calculates its
own MAC.

Then:

``` go
hmac.Equal(receivedMAC, expectedMAC)
```

This can help detect modified requests, forged requests, and clients
that do not possess the required secret.

Real systems often combine request signing with timestamps, nonces, or
request IDs to reduce replay attacks.

## 15. Three Progressively Challenging Exercises

### Exercise 1 --- Basic HMAC Generator

Write a Go program that:

1.  Defines a secret key.
2.  Defines a message.
3.  Generates an HMAC-SHA256.
4.  Prints the result in hexadecimal.
5.  Generates the same HMAC twice and verifies that both results are
    identical.

**Goal:** Become comfortable with `hmac.New`, `Write`, and `Sum`.

### Exercise 2 --- Message Authentication

Create two functions:

``` go
generateMAC(...)
verifyMAC(...)
```

Your program should:

1.  Generate an HMAC for a message.
2.  Verify the original message.
3.  Modify the message.
4.  Verify the modified message.
5.  Demonstrate that the original MAC is no longer valid for the
    modified message.
6.  Use `hmac.Equal` for the comparison.

**Goal:** Understand the complete HMAC generation and verification
workflow.

### Exercise 3 --- Secure API Request Signing

Build a small HTTP client/server application.

The client should send:

``` text
HTTP method
URL path
timestamp
request body
HMAC signature
```

The server should:

1.  Receive the request.
2.  Reconstruct exactly what the client signed.
3.  Generate its own HMAC.
4.  Compare the received signature using `hmac.Equal`.
5.  Reject requests with invalid signatures.
6.  Reject requests whose timestamps are outside an acceptable time
    window.
7.  Demonstrate what happens when an attacker modifies the request body.
8.  Demonstrate what happens when an attacker attempts to reuse an old
    request.

**Goal:** Move from learning the API to understanding how HMAC
participates in a real authentication protocol.

## 16. Most Important Things to Remember

Mental model:

``` text
                 SECRET KEY
                     │
                     ▼
MESSAGE ───────► HMAC-SHA256
                     │
                     ▼
                  MAC/tag
```

Verification:

``` text
                    SECRET KEY
                        │
                        ▼
MESSAGE ──────────► HMAC-SHA256
                        │
                        ▼
                  EXPECTED MAC
                        │
RECEIVED MAC ──────────┤
                        ▼
                  hmac.Equal()
                        │
                  ┌─────┴─────┐
                  ▼           ▼
                VALID       INVALID
```

The two exported `crypto/hmac` functions are:

  -----------------------------------------------------------------------
  Function                            Purpose
  ----------------------------------- -----------------------------------
  `hmac.New()`                        Creates an HMAC hash using a hash
                                      function and secret key

  `hmac.Equal()`                      Safely compares two MACs
  -----------------------------------------------------------------------

The returned `hash.Hash` also gives you methods such as `Write()` and
`Sum()` for feeding data into the HMAC and obtaining the resulting MAC.

### One deeper point

HMAC is not simply:

``` text
hash(message + key)
```

It is a specific standardized cryptographic construction involving the
secret key and the underlying hash function. Use Go's standard
`crypto/hmac` implementation instead of trying to design or implement
your own construction.

## Thought-Provoking Question

Imagine you build an API where **10 different microservices all share
the same HMAC secret key**.

One microservice is compromised.

**Can the other services still trust HMAC authentication? What security
problem does sharing the same HMAC key create, and how would the design
change if you wanted each service to be able to verify signatures
without being able to create them?**

This gets to the fundamental difference between **HMAC (symmetric
authentication)** and **public-key digital signatures (asymmetric
authentication)**.
