# `go.sum` File in Go

## 1. What is `go.sum`?

The **`go.sum`** file is a file automatically maintained by Go's module system. It contains **cryptographic checksums (hashes)** for the specific versions of dependencies used by a Go module.

### Purpose

The main purposes of `go.sum` are:

- **Verify dependency integrity** — ensures downloaded modules haven't been unexpectedly modified.
- **Record dependency checksums** — stores hashes associated with module versions.
- **Support reproducible builds** — helps different developers and environments verify the same dependencies.
- **Improve supply-chain security** — protects against accidentally or maliciously altered dependency contents.

A typical Go project may look like:

```text
myproject/
├── go.mod
├── go.sum
└── main.go
```

### `go.mod` vs `go.sum`

| File | Main purpose |
|---|---|
| `go.mod` | Describes the module and required dependency versions |
| `go.sum` | Stores checksums used to verify dependency contents |

Think of it this way:

> **`go.mod` tells Go what dependencies and versions the project needs.**  
> **`go.sum` helps Go verify that the downloaded dependencies are authentic and unchanged.**

### When is `go.sum` commonly used?

You will encounter it whenever your Go project uses external modules.

For example:

```bash
go get github.com/gorilla/mux
```

Go may update both:

```text
go.mod
go.sum
```

# 2. Simple Example Demonstrating `go.sum`

Let's create a small Go project that uses the Gorilla Mux package.

### Step 1: Create a project

```bash
mkdir myproject
cd myproject
```

Initialize a Go module:

```bash
go mod init example.com/myproject
```

You will get:

```text
myproject/
└── go.mod
```

### Step 2: Install a dependency

```bash
go get github.com/gorilla/mux
```

Now your project might contain:

```text
myproject/
├── go.mod
└── go.sum
```

Your `go.mod` could contain something similar to:

```go
module example.com/myproject

go 1.23

require github.com/gorilla/mux v1.8.1
```

And `go.sum` contains checksum entries similar to:

```text
github.com/gorilla/mux v1.8.1 h1:...
github.com/gorilla/mux v1.8.1/go.mod h1:...
```

The actual checksum values are generated by Go, so **you normally should not manually edit them**.

### Step 3: Use the dependency

Create `main.go`:

```go
package main

import (
	"fmt"
	"net/http"

	"github.com/gorilla/mux"
)

func homeHandler(w http.ResponseWriter, r *http.Request) {
	fmt.Fprintln(w, "Hello from Go!")
}

func main() {
	router := mux.NewRouter()

	router.HandleFunc("/", homeHandler).Methods("GET")

	fmt.Println("Server running on :8080")

	http.ListenAndServe(":8080", router)
}
```

Run:

```bash
go run .
```

Go uses the module information and checksums when resolving and verifying dependencies.

### Important commands

You will frequently use:

```bash
go mod tidy
```

This cleans and synchronizes your module dependencies and can add/remove entries in `go.sum`.

You can also download dependencies with:

```bash
go mod download
```

And verify downloaded modules:

```bash
go mod verify
```

# 3. Three Common Mistakes and Misconceptions

## Mistake 1: Manually editing `go.sum`

Beginners sometimes open `go.sum` and try to add or change checksum values.

Avoid manually changing entries such as:

```text
h1:xxxxxxxx...
```

### Better approach

Let Go manage it:

```bash
go mod tidy
```

or:

```bash
go get <module>
```

**Rule:** Usually, don't manually modify `go.sum`.

---

## Mistake 2: Thinking `go.sum` specifies dependency versions

A common misconception is:

> "`go.sum` tells Go which version of a dependency to use."

That's primarily the job of **`go.mod`**.

For example:

```go
require github.com/gorilla/mux v1.8.1
```

is dependency/version information in `go.mod`.

`go.sum` contains checksums associated with module versions and their `go.mod` files.

### Remember

```text
go.mod → dependency requirements
go.sum → dependency integrity checks
```

---

## Mistake 3: Deleting `go.sum` without understanding the consequences

A beginner may think:

> "`go.sum` is generated automatically, so I can always delete it."

Go can regenerate needed entries, but deleting it unnecessarily can cause dependency checksums to be downloaded and regenerated again.

It is generally better to **commit `go.sum` to version control** for projects that use dependencies.

For example:

```bash
git add go.mod go.sum
git commit -m "Add Go module dependencies"
```

# 4. Two Real-World Applications

## Application 1: Team Development

Imagine five developers working on the same Go backend project.

The repository contains:

```text
project/
├── go.mod
├── go.sum
└── main.go
```

Developer A installs the dependencies.

Developer B clones the project:

```bash
git clone <repository>
cd project
go mod download
```

The `go.sum` file provides checksum information that Go can use to verify module contents.

This helps provide greater consistency across developer machines and build environments.

---

## Application 2: CI/CD and Production Builds

Suppose your Go application is automatically built using a CI/CD system:

```text
GitHub
   ↓
CI/CD Pipeline
   ↓
go build
   ↓
Docker Image
   ↓
AWS/Kubernetes
```

The project contains:

```text
go.mod
go.sum
```

During the build, Go downloads required dependencies and verifies their checksums.

This is particularly valuable in production environments because dependency integrity becomes part of your software supply-chain security.

## 🟢 Exercise 1 — Beginner: Create and Observe `go.sum`

Create a new Go module.

Requirements:

1. Initialize a Go module using `go mod init`.
2. Add one external dependency.
3. Observe the changes to `go.mod`.
4. Observe the creation of `go.sum`.
5. Open `go.sum` and identify the checksum entries.
6. Run the project successfully.
7. Run `go mod verify` and observe the result.

**Goal:** Understand why `go.sum` appears and what information it contains.

Requirements:

1. Initialize a Go module.
2. Add the routing dependency.
3. Create at least two API endpoints.
4. Check the contents of `go.mod`.
5. Check the contents of `go.sum`.
6. Run `go mod tidy`.
7. Observe whether `go.mod` or `go.sum` changes.
8. Run `go mod verify`.
9. Commit both `go.mod` and `go.sum` to Git.

**Goal:** Understand how dependency management and checksum verification work together.

Create a small Go project that uses **at least three external dependencies**.

Requirements:

1. Initialize the project with Go modules.
2. Add three external dependencies.
3. Use all three dependencies in your application.

# Quick Summary

```text
                 Go Project
                     │
             ┌───────┴───────┐
             │               │
          go.mod           go.sum
             │               │
             ▼               ▼
     What dependencies?   Are they authentic?
     Which versions?      Checksum verification
```

### Remember this simple rule:

> **`go.mod` = dependency requirements**  
> **`go.sum` = dependency checksums/integrity verification**

And in a typical project:

```text
myproject/
├── go.mod     ← Module + dependency requirements
├── go.sum     ← Dependency checksums
└── main.go    ← Application code
```
